\section{Technical Examples}

\subsection{Algorithm Block}

Algorithm~\ref{alg:template} shows a simple structure for documenting an experiment pipeline. The pseudocode is intentionally generic. Replace the setup, execution, and recording steps with the operations used by the real project.

\begin{algorithm}[H]
\caption{Generic Experiment Pipeline}
\label{alg:template}
\begin{algorithmic}[1]
\Require Scenario set $S$, trial count $r$, random seed $seed$
\Ensure Result table $R$
\State Initialize deterministic randomness using $seed$
\State $R \gets \emptyset$
\ForAll{$s \in S$}
  \For{$i \gets 1$ to $r$}
    \State Generate input material for scenario $s$
    \State Execute the implementation under test
    \State Record success flag, runtime, and output size
  \EndFor
\EndFor
\State \Return aggregate statistics in $R$
\end{algorithmic}
\end{algorithm}

\subsection{Equations}

Equations should be introduced in prose and referenced when they matter. For instance, an average latency metric can be written as
\begin{equation}
  \bar{L} = \frac{1}{n}\sum_{i=1}^{n} L_i,
  \label{eq:latency}
\end{equation}
where $L_i$ is the latency observed in trial $i$ and $n$ is the number of trials. Equation~\eqref{eq:latency} is useful only if the text explains how measurements are collected, filtered, and interpreted.
